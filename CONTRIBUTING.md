# Работа команды с репозиторием

Это предложенный процесс с 22.11.2026. Он не описывает незафиксированные прошлые встречи или PR.

1. Руководитель выбирает приоритет из [бэклога](agile/backlog.md).
2. Тимлид уточняет историю, критерии, зависимости, ответственного и оценку. В задаче должно быть понятно, как проверить результат.
3. Разработчик создаёт отдельную ветку, например `feature/AG-08-prices` или `fix/AG-07-map`, и делает небольшие осмысленные коммиты со ссылкой на Issue.
4. Изменения попадают в Pull Request. Мариам проверяет сценарии, Вера просматривает код и данные. Поскольку пока известен только один GitHub-логин, имена других участников указаны в тексте, назначения в чужие аккаунты не выдумываются.
5. После проверок и приёмки PR объединяют с main. Разработчик запускает публикацию Render и проверяет опубликованную версию. При сбое используют предыдущий успешный deploy, не переписывают историю Git.
6. Ответственный прикладывает доказательства в Issue и закрывает её. Тимлид обновляет доску и файлы среза.

## Локальный запуск

Статический сайт: откройте папку через локальный HTTP-сервер, например `python -m http.server 8000`. Карта использует ключ с ограничением домена Render; работа карты на localhost не обещается. Каталог работает независимо.

## Проверки

Нужен Node.js 22. Внешних npm-зависимостей нет. Запустите `npm test` из корня.
Проверки данных и синтаксиса не заменяют ручную проверку карты, мобильной версии и маршрутов.

Обновление Agile-страницы: правка `agile/backlog.json`, затем `npm run agile:build`.
Повторяемая статистика: `node tools/git-report.mjs <commit>`.
